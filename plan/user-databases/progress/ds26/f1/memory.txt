Remaining peak (~1.9x the value) is libpq itself: the DataRow is read whole into its input
buffer and copied into the PGresult before any client code can look at it. Only a
server-side bound could avoid it; Postgres has no setting for that, and wrapping the
model's SQL to cap each column would change its semantics (so it wasn't done). The value
is still bounded by Postgres's 1 GB field limit and by the statement timeout.
